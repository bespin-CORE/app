# 구현 판단

- Task 1: 기존 H2 스키마가 테스트마다 테이블을 삭제하므로 새 테이블도 의존성 순서로 삭제하고, 비활성 메일 연결이 헬스 체크를 실패시키지 않도록 메일 헬스 지표를 끈다.
- Task 2: 텍스트 렌더러는 기존 의존성에서 OGNL이 없어 Spring 표현식을 쓰는 `SpringTemplateEngine`을 별도로 사용하며, 오류에는 민감한 예외 메시지 대신 예외 종류만 저장하고 중복 키가 아닌 무결성 오류는 다시 던진다.
- Task 3: 가입 폼의 주소는 앞뒤 공백을 허용하도록 정규화한 뒤 검증하되 제어문자는 정규화 전에 거부하고, 인증 경쟁의 UNIQUE 충돌은 별도 트랜잭션 경계에서 처리한다.
- Task 4: 기존 예약 변경은 벌크 UPDATE이므로 메일 작성 전 엔티티를 새로 읽어 변경된 상태와 내용을 반영한다.
- Task 5: 사전 알림은 기존 예약 모델을 사용하여 오늘과 내일의 예약을 함께 조회하고 개별 트랜잭션으로 중복 키를 기록한다.
- Task 6: 비밀번호 확인 오류는 기존 Thymeleaf 폼 패턴에 맞춰 `BindingResult` 필드 오류로 표시한다.
- Task 7: Spring Session JDBC가 테스트 요청의 세션을 쿠키로 전달하므로 팝업 닫기 검증은 반환된 세션 쿠키를 재사용한다.
- Task 8: 기존 MVC 슬라이스 테스트에는 새 공통 advice 의존성을 모킹하고, 동시에 들어온 계정별 토큰 요청도 시간당 제한을 지키도록 사용자 행 잠금과 동시성 검증을 추가한다. MySQL의 외래 키가 명시적으로 생성되도록 세 스키마에서 테이블 수준 FOREIGN KEY를 사용한다.

## 개정 1

- R1: 가입 검증은 컨트롤러에서 원본 제어문자를 거부한 뒤 정규화하며, 사용자 저장 예외는 별도 서비스 트랜잭션이 롤백된 후 폼 오류로 변환한다.
- R2: Spring Security의 기본 비활성 검사는 비밀번호 확인 전 실행되므로 인증 공급자의 비활성 검사를 비밀번호 확인 뒤로 옮겨 잘못된 비밀번호에는 계정 상태를 노출하지 않는다.
- R3: 변경 경로를 제거하고 인증 및 비밀번호 재설정은 검증 주소가 변경 불가능한 아이디와 같은 계정만 허용한다.
- R4: 중복 키 선조회는 본문 생성만 생략하며 동시 실행의 최종 중복 방지는 기존 UNIQUE 제약과 별도 트랜잭션에 맡긴다.
- R5: 보안 공급자가 필요한 기존 독립 MVC·오류 테스트에는 사용자 상세 서비스를 모킹한다. 중복 가입 시 Hibernate 경고에 이메일이 포함되어 JDBC 오류 로거의 WARN을 억제하며, 이에 따라 다른 JDBC WARN도 출력되지 않는다.
