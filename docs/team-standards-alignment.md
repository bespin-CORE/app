# 팀 통합 기술 규격 적용 현황

출처: 사용자가 제공한 `agent.md 통합본` HTML. 이 문서는 통합본의 목표와 현재 저장소의 확인 결과를 구분한다. 기준일: 2026-11-15. 최종 아키텍처 및 일정은 팀 의사결정에 따라 변경될 수 있다.

| 항목 | 팀 목표 | 현재 확인 결과 | 다음 작업 |
| --- | --- | --- | --- |
| 저장소 경계 | 앱·Terraform 저장소와 GitOps 저장소 분리 | 앱(루트)과 `docs/`가 같은 저장소에 있다. 별도 GitOps 저장소는 이 작업에서 확인하지 않았다. | 저장소 소유자·구조 확정 후 이전 계획 수립 |
| 빌드 | Gradle 단일화, Java 17 | Maven과 Gradle이 공존한다. 2026-11-16에 JDK 17로 `./gradlew clean check`가 통과했다(테스트 135건 중 실패 0, 건너뜀 4). | 배포 절차와 Buildpacks 이미지 빌드를 확인한 후 Maven 제거 여부 결정 |
| DB 스키마 | Flyway, 운영 초기화 금지, JPA validate | MySQL 설정은 `spring.sql.init.mode=always`, JPA는 `ddl-auto=none`이다. Flyway 전환은 완료되지 않았다. | 기존 DB 백업·베이스라인·시드 분리·롤백 절차를 설계하고 검증 |
| 관리 포트 | 앱 8080, Actuator 8081 분리 | 현재 설정에는 관리 포트 분리가 없다. 임시 서버는 Nginx에서 외부 `/actuator` 접근을 차단한다. | 프로브·모니터링 연동을 포함해 포트 분리 검증 |
| DB 자격 증명 | 시크릿 주입, 기본 비밀번호에 의존하지 않음 | MySQL 설정에 로컬 기본값이 존재한다. 임시 서버는 별도 환경 변수로 주입한다. | 로컬 개발과 운영 설정 분리 및 필수 주입 검증 |
| AWS/GCP 인프라 | 서울 리전 Primary/Warm Standby, 원격 state, GitOps | 이 저장소에 `infra/`는 없다. 임시 서비스는 Proxmox VM에서 실행 중이다. | 설계·권한·비용 및 복제 PoC 검증 후 별도 구현 |
| 이미지·CI/CD | Gradle Buildpacks, SHA 이미지, ECR·Artifact Registry, Argo CD | 현재 파일에 원본 워크플로가 있으나 목표 파이프라인 구현·동작은 확인되지 않았다. | 두 레지스트리와 GitOps 배포 흐름 설계·검증 |
| 관측성 | JSON 구조화 로그, traceId, 관리 엔드포인트 격리 | 일부 Actuator 엔드포인트가 설정돼 있다. 구조화 로그·분산 추적은 검증하지 않았다. | 로그·메트릭·권한 경계 구현 및 검증 |

팀 통합본의 기존 `k8s/` 및 Maven 파일 즉시 제거 제안은 현재 실행 경로와 테스트를 확인하기 전에는 적용하지 않았다. 또한 로컬 Terraform state 금지 규칙은 AWS/GCP 목표에 적용할 사항으로 기록했으며, 이미 운영 중인 Proxmox 임시 환경에 대한 state 이관은 수행하지 않았다.

## 우선순위 제안

1. Gradle 빌드와 MySQL 스키마의 현 상태를 재현하고, Flyway 도입 시 기존 임시 데이터 보존 방식을 합의한다.
2. GitOps 저장소, Notion DR 원본, 클라우드 계정·권한 및 서울 리전 DR 범위를 확인한다.
3. 관리 포트와 시크릿 주입을 설계하고 앱·프로브·배포 설정을 함께 검증한다.
4. Terraform 원격 state와 이미지 배포 경로를 준비한 후 복제·복구 PoC를 진행한다.
